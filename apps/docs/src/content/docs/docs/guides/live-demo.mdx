The live demo is a Shamar panel that is already running, with data that is already seeded. It exists so you can click through lists, forms, media, and roles before you install anything. The credentials reset on a timer because the demo is shared: anyone can change records, and the next wipe puts the original set back.

It is the same software as an installed panel. The playground happens to store those records in MongoDB. Your app can use MongoDB or SQL. The screens you see here are not a mockup of a different product.

The live panel is on a separate host: **[demo.shamar.dev](https://demo.shamar.dev/)** (sign in at [demo.shamar.dev/login](https://demo.shamar.dev/login)).

## What you can try

- Admin panel at [demo.shamar.dev](https://demo.shamar.dev/) — products, companies, media, settings pages
- File manager + `FilePicker`
- Rich editors (simple / notion / document)
- Roles, permissions, and API keys

## How resets work

Every **20 minutes** the demo:

1. Wipes the Mongo database
2. Re-seeds users, catalog data, and roles
3. Publishes a fresh `nextResetAt` on `GET https://demo.shamar.dev/demo-status`

Sessions bound to old user ids stop working after a wipe — sign in again with the credentials above.
