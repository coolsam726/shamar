---
title: Infolists overview
description: Show/detail views for resources and pages.
---

An infolist is the read-only view of one record, the show page. A form collects input. An infolist only displays what is already stored: a name, a colored swatch, an icon for a boolean, a thumbnail. People use it when they need to look at a record without the risk of editing it, or when the edit form would be the wrong density for a quick check.

You describe it with `infolist()`, using entries instead of inputs. `TextEntry.make('name')` reads the same model attribute a `TextInput` would edit. Sections group entries the same way they group fields. If you omit an infolist, the panel can still show a record from the form's fields, but a dedicated infolist is how you choose a different layout for reading than for writing.

```ts
static infolist(infolist: InfolistBuilder) {
  return infolist.schema([
    Section.make('Product').columns(3).schema([
      TextEntry.make('name'),
      IconEntry.make('featured').boolean(),
      ColorEntry.make('color'),
    ]),
  ])
}
```

Infolists power resource **show** pages and can be composed on [ListPage](/docs/reference/pages/list-page/) rows.

## Entry types

| Entry | Use |
|-------|-----|
| [TextEntry](/docs/reference/infolists/text-entry/) | Text, badges, dates, currency, markdown |
| [IconEntry](/docs/reference/infolists/icon-entry/) | Icons and boolean icons |
| [ColorEntry](/docs/reference/infolists/color-entry/) | Color swatches |
| [ImageEntry](/docs/reference/infolists/image-entry/) | Thumbnails |

## Auto-derivation

If you omit `infolist()`, Shamar builds a show view from `form()` via `formSchemaToInfolistSchema()`.

**Playground:** Products — explicit infolist with all entry types.
