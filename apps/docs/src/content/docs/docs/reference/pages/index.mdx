A page is an admin screen that is not the CRUD of one model. Settings, a custom list that does not map to a resource class, a dashboard of charts, or a mixed layout all fit here. Resources cover "manage these records." Pages cover "give staff somewhere else to go" that still lives in the same sidebar, the same auth, and the same panel chrome.

The host discovers page classes from a directory you name on the panel, the same way it discovers resources. `slug` is the URL segment. `canAccess()` is the optional gate. The class you extend — `SettingsPage`, `DashboardPage`, `ListPage`, `FormPage`, or a plain `Page` — decides which screen shape you get. Pick the shape first, then open that page's reference. This overview is only the choice.

```ts
panel('admin').discoverPages('app/panels/admin/pages')
```

| Page type | Class | Use |
|-----------|-------|-----|
| [FormPage](/docs/reference/pages/form-page/) | `FormPage` | One-off form |
| [SettingsPage](/docs/reference/pages/settings-page/) | `SettingsPage` | App settings singleton |
| [ListPage](/docs/reference/pages/list-page/) | `ListPage` | Standalone table |
| [DashboardPage](/docs/reference/pages/dashboard-page/) | `DashboardPage` | Widget grid home |
| [Composite Page](/docs/reference/pages/composite-page/) | `Page` + `pageContent()` | Mixed sections |

Shared static props: `slug`, `label`, `navigationGroup`, `icon`, `canAccess()`.

```bash
node ace shamar:make-page Settings --type settings
```
